# 短縮URLのクリック計測 仕様書

WordPress側の短縮URLプラグインに手を入れて、アフィリエイトリンクのクリックを
GA4で計測できるようにする。**この文書だけで作業できるように書いてある。**

- 作成日: 2026-09-06
- 対象: `tabidachi.org` 配下の全サイト（現時点17サイト）と `hokkaido-travel.org`
- 前提の理解: §1 を必ず読むこと。読まずに実装すると別の方法を選んでしまう

---

## 1. なぜ必要か（ここを外すと設計を誤る）

アフィリエイトリンクは自前の短縮URLプラグインによって、**自ドメインのURL**として
出力されている。

```html
<a href="https://fukuoka.tabidachi.org/go/5fqm9k" target="_blank" rel="noopener noreferrer">
```

GA4の拡張計測が自動で出す `click` イベントは、**現在のドメインと異なるドメインへの
リンクだけ**が対象。`/go/xxx` は自ドメインなので `click` は発生しない。
さらに `/go/xxx` はサーバー側で301リダイレクトされるため、HTMLが返らず
`page_view` にもならない。

**結果として、現在アフィリエイトのクリックはGA4のどこにも記録されていない。**
（拡張計測そのものは正常に動作している。`scroll` などは記録されている）

したがって、**クリック時に独自のイベントを送る**しか方法がない。

---

## 2. 担当の分割

| 担当 | やること |
|---|---|
| **短縮URLプラグイン**（この仕様書の作業対象） | リンクのHTMLに `data-*` 属性を出力する。**イベント送信はしない** |
| GA4計測タグ `ga4-tracking.php`（別途こちらで対応） | `data-*` を読んでクリック時に `gtag()` で送信する |
| GA4の設定 | カスタムディメンションを登録する（別途こちらで対応） |

**この分割を変えないこと。** GA4の知識を1か所（計測タグ）に閉じ込めるための分割で、
プラグイン側に `gtag()` を書くと、サイトごとに計測仕様がばらつく原因になる。

---

## 3. プラグイン側の作業

### 3.1 出力するもの

短縮URLのアンカータグに、以下の属性を追加する。**既存の属性は変えない。**

```html
<a href="https://fukuoka.tabidachi.org/go/5fqm9k"
   target="_blank" rel="noopener noreferrer"
   data-ga4-click="affiliate"
   data-ga4-code="5fqm9k"
   data-ga4-domain="travel.rakuten.co.jp"
   data-ga4-label="ホテルグレイスリー福岡">
```

| 属性 | 必須 | 内容 | 制約 |
|---|---|---|---|
| `data-ga4-click` | 必須 | 固定値 `affiliate`。計測タグはこの属性の有無だけでリンクを判別する | — |
| `data-ga4-code` | 必須 | 短縮コード（`/go/` の後ろ） | 100文字以内 |
| `data-ga4-domain` | 推奨 | **転送先のホスト名のみ**。スキームもパスも付けない | 100文字以内 |
| `data-ga4-label` | 任意 | 宿名・案件名など、人間が見て分かる名前 | **100文字以内に切り詰めてから出力すること** |

### 3.2 なぜ転送先URL全体を出さないのか

GA4のイベントパラメータは**値が100文字までで、超えた分は切り捨てられる**。
アフィリエイトURLはパラメータが長く、ほぼ確実に100文字を超えて途中で切れる。
切れたURLは復元できず、集計に使えない。

**ホスト名だけを送り、完全なURLはプラグインのDBに残す。** `data-ga4-code` を
キーにすれば後から突き合わせられる。ダッシュボード側もこの前提で作る。

### 3.3 適用範囲

- **記事本文中のリンクだけでなく、ウィジェット・ショートコード・ブロックなど
  短縮URLを出力するすべての箇所**に適用する
- 管理画面のプレビューや編集画面には出力しなくてよい
- 出力が重い場合、属性の付与は短縮URL生成時ではなく**出力時のフィルタ**で行ってよい

### 3.4 やってはいけないこと

- **個人を特定しうる値を属性に入れない**（ユーザーID・メールアドレス・注文番号など）。
  GA4は個人情報の送信を規約で禁止しており、違反するとプロパティが停止されうる
- `href` を書き換えない。リダイレクトの仕組みには触れない
- `data-ga4-label` に記事タイトル全文のような長い文字列を入れない（100文字で切る）

## 4. 計測タグ側の仕様（参考・こちらで実装する）

プラグイン側の実装が正しいかを判断するために載せる。**この節の作業は不要。**

```js
document.addEventListener('click', (e) => {
  const a = e.target.closest('a[data-ga4-click="affiliate"]');
  if (!a) return;
  gtag('event', 'affiliate_click', {
    link_code:   a.dataset.ga4Code   || '',
    link_domain: a.dataset.ga4Domain || '',
    link_label:  (a.dataset.ga4Label || '').slice(0, 100),
    page_path:   location.pathname,
  });
}, { capture: true });
```

- `capture: true` で拾う。テーマ側のJSが `stopPropagation()` する場合に取りこぼさないため
- `target="_blank"` なので現在のページは遷移せず、送信は完了する
- 中クリック・キーボード操作は `click` で拾えない場合がある。取りこぼしは許容する
  （厳密な突合はプラグイン側のリダイレクトログで行う方が確実）

### GA4側の設定（こちらで対応）

`link_code` / `link_domain` / `link_label` を**イベントスコープのカスタム
ディメンション**として登録する。登録しないとレポートとData APIで参照できない。

## 5. 完了条件

以下がすべて満たされていること。**「実装した」ではなく「出ている」まで確認する。**

1. 記事ページのHTMLに `data-ga4-click="affiliate"` を持つアンカーが出力されている

   ```bash
   curl -sS https://fukuoka.tabidachi.org/asakura-family-bath-ryokan-2026/ \
     | grep -o 'data-ga4-[a-z]*="[^"]*"' | sort -u
   ```

2. `data-ga4-code` が `href` の `/go/` の後ろと一致している
3. `data-ga4-domain` が転送先のホスト名になっている（スキーム・パスを含まない）
4. `data-ga4-label` が100文字を超えていない
5. 17サイトすべてで出力されている（共通プラグインなら1サイトの確認で足りる）
6. 既存のリンクの見た目・挙動（`target` / `rel` / リダイレクト）が変わっていない

### 動作確認の順番

1. プラグインを更新し、上記1〜6を確認
2. 計測タグ側の対応を入れる（こちらで実施）
3. 実際に短縮リンクをクリックし、**GA4のリアルタイム**で `affiliate_click` が
   出ることを確認する。日次レポートは反映に24〜48時間かかるため、確認は
   リアルタイムで行う

## 6. 補足

- 計測タグは管理者としてログイン中は何も出力しない（`GA4_SKIP_ADMIN`）。
  動作確認はログアウトした状態か、シークレットウィンドウで行うこと
- イベント名 `affiliate_click` は変更しないこと。ダッシュボード側がこの名前で集計する
- パラメータ名は40文字以内・値は100文字以内（GA4の制限）
- 1イベントにつきパラメータは25個まで。将来項目を足す場合も余裕はある
